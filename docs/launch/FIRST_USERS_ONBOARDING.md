# First Users Onboarding

Use placeholders only. Do not store real personal data in this document.

## First User Criteria

| Criterion | Requirement |
| --- | --- |
| Organization | Small test organization with named support contact |
| Consent | User understands beta/soft launch status |
| Scope | One narrow workflow at a time |
| Support | Manual support owner assigned |
| Data | No unnecessary sensitive data in test notes |

## Account Setup

1. Create account for `user@example.test`.
2. Assign organization `Example Test Organization`.
3. Assign role according to test plan.
4. Confirm the user can sign in.
5. Confirm the user cannot access another organization.

## Document Access Flow

1. Confirm whether checkout is disabled, sandbox or separately approved live.
2. Grant access manually if paid commerce is disabled.
3. Complete document input only with placeholder-safe content unless legal owner approves real data.
4. Generate one document.
5. Verify secure download.
6. Record job ID and support notes.

## Problem Reporting

- Support channel: `support@example.test`.
- Ask for account email, organization name, approximate time, route/action and screenshot if safe.
- Do not ask users to send secrets, passwords or full sensitive datasets by email.

## First-Use Monitoring

- Auth success/failure.
- Portal route access.
- CRM lead visibility for staff.
- Document job status.
- Download authorization.
- Email delivery if enabled.
- Any user confusion or legal wording issues.

## Feedback Capture

Record:

- what task user tried,
- whether it completed,
- where they hesitated,
- support ticket ID,
- blocker severity,
- follow-up owner.
